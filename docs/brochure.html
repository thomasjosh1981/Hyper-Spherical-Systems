How It Works

From Raw Request to Optimized Inference

When any AI client on your system makes an API call — whether it's Hermes Agent, Open WebUI, Cursor, or a raw Python script — the Pirate Llama Auto-Intercept Engine transparently captures that request on its loopback port clone. No client configuration required.

The intercepted payload passes through a 4-layer compression pipeline: phrase canonicalization → ISSI (Integer String Substitution Index, pronounced "Izzy") homophonic dictionary encoding → ChaCha20-Poly1305 optional encryption → context window slot optimization. The result is a semantically identical prompt that occupies a fraction of the original token budget.

The compressed request is then scored by the BMRAD Brain Governor, which routes it to the best available backend: local (Ollama/llama.cpp), peer SFS+ model, or cloud. Responses are decompressed transparently before being returned to the client.

ISSI — Integer String Substitution Index

🗜️

Phase 1: Phrase Canonicalization

A 200+ entry canonical phrase table maps common LLM boilerplate ("You are a helpful assistant", "Based on the context") to ultra-compact §-prefixed codes. Applied in O(n) over prompt length.

Typical gain: 1.4× — 2.1×
🔤

Phase 2: Homophonic Dictionary

Domain-adaptive per-session character → phrase mappings. In CODING mode: single unicode char replaces "function", "return", "import". Symbols recycled across the session window.

Typical gain: 2.5× — 5×
🧮

Phase 3: MNECP Handshake

Model-Negotiated Ephemeral Compression Protocol. On session open, HypeS sends a compact handshake header. If the model acknowledges, subsequent messages use the negotiated codec.

Typical gain: 7× — 10×

Module Reference

20 Engine Modules. One Unified Stack.

🧠 Brain Director & Governor

BMRAD · CompetitiveGrowthEngine · HardcodedKnowledgeBase

The master governor for all inference decisions. Maintains a persistent skill knowledge base in ~/.hypes/hardcoded_knowledge.json. Knowledge is never deleted — only logically upgraded via version-tracked replacement records. The CompetitiveGrowthEngine absorbs superior skills from peer models using cosine-similarity matching (threshold 0.82).

PerplexityMonitor RecursiveConsensusAuditor AttentionAnalyzer LoopDetector

🗜️ ISSI + CCTM + Holy Grail

Context Compression Cramming & Declutterizer

Three-phase compression engine. Phase 1: canonical phrase substitution (200+ entries). Phase 2: domain-adaptive homophonic dictionary (CODING / ROLEPLAY / DATA / GENERAL). Phase 3: MNECP session negotiation for model-native compression. Plus the Holy Grail CCTM (Cloud Context Token Manager) for multi-session KV-cache reuse.

10× Peak Ratio Session-Scoped Zero-Loss Roundtrip

🔮 4D Hyperspherical Memory Router

HypersphericalCacheManager · TokenShredderEngine

Models layers as 4D coordinate points on a hypersphere. Load radius (0.75) and stay buffer (0.20) determine which layer tensors remain resident in VRAM, which page to NVMe, and which are prefetched speculatively via the predictive prefetcher. PCIe pipeline saturation modes: ADAPTIVE, FIXED_64K to FIXED_512K.

VRAM Streaming NVMe Prefetch PCIe Saturator

Cloud API keys are auto-detected in Authorization headers and bypass the local stack. All intercepted traffic is compressed via ISSI, routed by BMRAD, and forwarded to the real backend. All context payloads optionally encrypted before leaving the local stack. The 5+1 homophonic cipher encodes content into unicode clusters indistinguishable from natural language.
